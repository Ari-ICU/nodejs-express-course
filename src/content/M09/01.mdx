  summary: `**Representational State Transfer (REST)** is an architectural style for designing networked applications and distributed hypermedia systems, formulated in 2000 by Roy Fielding in his doctoral dissertation.

### 1. Fundamental Philosophy
Unlike RPC (Remote Procedure Call) or SOAP which focus on remote method execution, REST models the domain as a universe of **Resources** identified by uniform URIs. Clients manipulate these resources by transferring representations (typically JSON or XML) via standard HTTP operations.

### 2. Core Operational Pillars
* **Resource-Centric**: Every key business entity (user, order, product) has a unique addressable URI (e.g., \`/api/v1/orders/102\`).
* **HTTP as the Application Protocol**: Uses native HTTP methods (\`GET\`, \`POST\`, \`PUT\`, \`PATCH\`, \`DELETE\`) rather than custom verbs in URLs.
* **Decoupled Architecture**: Clients do not need internal knowledge of the server's database schema, server language, or internal storage engine.`,
