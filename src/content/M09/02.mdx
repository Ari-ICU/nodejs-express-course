### The 6 Foundational Constraints:
1. **Client-Server Architecture**: Separates user interface and client concerns from data storage and server logic. Both can evolve independently without breaking contracts.
2. **Statelessness (Stateless)**: Every single request from client to server must contain all the information necessary to understand and process the request (e.g., Bearer JWT tokens in headers). The server retains zero client session state between requests.
3. **Cacheability**: Responses must explicitly label themselves as cacheable or non-cacheable to prevent clients from reusing stale or inappropriate data.
4. **Uniform Interface**: The cornerstone of REST. Standard resource identification (URIs), manipulation of resources through representations, self-descriptive messages, and hypermedia (HATEOAS).
5. **Layered System**: An intermediary (proxy, reverse proxy, load balancer, API gateway) can be inserted without the client knowing whether it is speaking to the end server or an intermediate cache.
6. **Code on Demand (Optional)**: Servers can temporarily extend or customize client functionality by transferring executable code (e.g., JavaScript).`,
