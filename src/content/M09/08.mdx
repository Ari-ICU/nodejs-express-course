### 1. Key Semantic Rules of PUT
* **Complete Replacement**: Any fields omitted in the incoming request body are either reset to default values or overwritten as \`null\` / undefined. It is NOT a partial merge.
* **Idempotence**: Sending the exact same PUT request multiple times leaves the server in the exact same state as sending it once.
* **Validation Requirements**: Because PUT replaces the full document, all mandatory fields must be validated exactly like in a POST request.
* **Status Code Selection**:
  * **200 OK**: When returning the updated resource representation in the response body.
  * **204 No Content**: When the update succeeds and the server chooses not to return an updated body.
  * **404 Not Found**: When the resource target identified by \`:id\` does not exist.`,
