### 1. Key Properties of an Enterprise Error Envelope
* **\`success: false\`**: Clearly indicates operation failure.
* **\`error.code\` (string)**: An uppercase, machine-readable constant (e.g. \`EMAIL_ALREADY_EXISTS\`, \`TOKEN_EXPIRED\`, \`PAYMENT_DECLINED\`). This enables frontends to trigger localized UI error messages without parsing natural language strings.
* **\`error.message\` (string)**: A clear, human-readable summary of the error.
* **\`error.details\` (array, optional)**: Field-specific validation breakdown identifying exact inputs that failed.
* **\`error.timestamp\` (ISO-8601)**: Useful for correlating client error reports with server logs.

### 2. Environment Security: Stripping Stack Traces
Never leak database error messages, SQL queries, or internal file paths (\`error.stack\`) in production. Malicious actors use stack traces to reverse-engineer server vulnerabilities.`,

const express = require("express");
const app = express();

// Custom Application Error Class
class AppError extends Error {
  constructor(message, statusCode, errorCode, details = null) {
    super(message);
    this.statusCode = statusCode;
    this.errorCode = errorCode;
    this.details = details;
    this.isOperational = true; // Distinguishes operational errors from code bugs

}

// Route triggering validation error

});
