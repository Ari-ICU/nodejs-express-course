// Why Bearer Tokens in headers are immune to CSRF:
// 1. In CSRF, a malicious website triggers: <form action="https://bank.com/transfer" method="POST">
// 2. The browser automatically attaches COOKIES.
// 3. The browser NEVER automatically attaches custom HEADERS like:
//    "Authorization: Bearer <token>"
//
// Therefore:
// - Bearer Auth (in Header): Immune to CSRF by design.
// - Cookie Auth: Requires SameSite="strict" or Anti-CSRF Synchronizer Tokens.
